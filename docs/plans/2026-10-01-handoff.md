## How to work this plan

- One section at a time. Finish its acceptance list, run its gates,
  commit, and push before starting the next.
- Gates for every section: `bun run test`, `bun run check`,
  `bun run lint`, plus the named e2e files in ONE Playwright
  invocation (`bunx playwright test a.e2e.ts b.e2e.ts --retries=0`).
  If `src-tauri/` changed: `cd src-tauri && cargo test --lib`.
- Never delete or weaken a test to make a gate pass. If a test pins
  behavior the section deliberately changes, update it and say why
  in the commit message.
- New pure logic goes in `src/lib/*.ts` with a `*.test.ts` next to
  it. Tests assert behavior (inputs → outputs, DOM after actions),
  not source text, unless the thing is CSS or layout jsdom can't see.
- Do not write "extraction" tests (asserting markup lives in file X,
  not file Y). Section E deletes exactly those.
- When a section is done, tick it here and add a line to
  `docs/DONE.md`.

## A. Giant text (owner priority: low-vision family member)

The owner's grandmother needs gigantic letters. Never narrow the
50–2000% range (`FONT_SCALE_MIN/MAX` in `settings.ts`). Evidence
from `e2e/giant-text.e2e.ts` (screenshots in `.screenshots/giant-*`):

1. Words break at arbitrary letters with no hyphen ("bedeut / et",
   "Donaudam / pfschifffahr"). Fix: give each rendered message body
   a `lang` attribute (the reply language, or the detected one via
   `identifyLangShort` / `messageSpeechLang`) and set
   `hyphens: auto` on message text, keeping the existing
   `overflow-wrap` as the last resort. WebKit (the shell) and
   Chromium both hyphenate de/fr/en when `lang` is set.
2. Desktop at 2000% keeps a ~575px column in a 1280px window. Phones
   go full-bleed at `fontScale >= FULLBLEED_FONT_SCALE` via
   `effectiveChatWidth`; desktop never does. Make desktop go
   full-bleed at large scales too (unit-test `effectiveChatWidth`
   for both platforms).
3. Phone at 2000% scrolls sideways (`.messages` 574 > 412). Find the
   element that spills (the spec's `overflowReport` lists them; also
   check `pre`, the table wrapper, the refs pill, and the article
   gutters) and contain it. Remove the `test.fail` line in the spec
   when it passes.
4. Line spacing scales with the text, so at 800% most of the screen
   is the gaps between lines. Tighten `line-height` as `--font-scale`
   grows (for example `clamp(1.15, …, 1.6)`) and reduce paragraph
   margins in em at large scales.
5. Check the composer, the toasts, the flashcard deck, and the
   settings drawer at 800% and 2000% (desktop and phone) and fix
   anything clipped. Add each surface to `giant-text.e2e.ts`.

Acceptance: all four `giant-text.e2e.ts` cases pass with no
`test.fail`; screenshots show hyphenated breaks and a full-width
desktop column at 2000%. Gates: `giant-text`, `layout`,
`composer-phone`, `android`, `chrome`.

Only after this holds: consider raising `FONT_SCALE_MAX` (owner says
2000% is "almost not wide enough"), at least on desktop.

## G. Correction mode (feature)

For French and German chats: the model marks the user's own mistakes
as well as replying. Design:
- A per-chat toggle next to the reply-language pill (default off;
  the pill row stays minimal, so the toggle only shows when a reply
  language is set).
- When on, the system prompt asks for a corrected version of the
  user's last message in a fenced block with a fixed tag (for
  example ` ```correction `), and the TS provider and `turn.rs`
  both treat it identically (AGENTS.md "Two engines" rule).
- Render: the user's message shows a small inline diff (deleted
  words struck through, inserted words underlined) under it, from a
  pure word-diff in `src/lib/correction.ts` (unit-tested, works
  across CJK too). The fenced block itself is hidden from the
  assistant body.
- Corrections can be annotated like any text, so they feed
  Flashcards for free.
Gates: unit tests for the diff and the parse; an e2e with the mock
provider returning a correction block.
